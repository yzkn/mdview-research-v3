## 1. 要件

### R-01. Markdown 以外のファイルの色付け

（README の制限事項「Markdown 以外のファイルはテキストとして扱う。言語ごとの色付けは無い」。v2.2.0）

- 拡張子から言語を決め、**編集画面とプレビューで言語ごとに色を付ける**（`.rs`・`.py`・`.js`・`.ts`・`.json`・`.yaml`・`.html`・`.css`・`.sh`・`.c`・`.java` など、
  コードブロックの色付け（syntect）が知っている言語）
- 色はコードブロックと同じ（テーマの明暗に合わせる）。知らない拡張子はいまどおり色無し
- **大きいファイルでも重くしない**。見えている所だけ色を付ける（いまのコードブロックの色付けと同じ考え方）。512 KB を超えるファイルでの扱いは設計で決める
- 設定で色付けを切れる（既定は付ける）
- 文書としての扱い（リストの続き・表の整形が効かない・プレビューで等幅のまま並べる）はいまと同じ

### R-02. 比べる画面での検索

（README の制限事項「比べる画面では検索を使えない」。v2.3.0）

- 比べる画面（2 面の比較・マージの 3 面）で `Ctrl + F` を押すと、**いま入力のある面**の検索の欄が開く
- 次・前の一致へ移り、一致に印を付ける（いまの検索と同じ見た目）。置き換え（`Ctrl + H`）も、直せる面では効く
- プレビューでの比較（読むだけ）では、検索だけ効く
- 比べる画面を閉じたら、検索の欄も閉じる

### R-03. KDE の中継先（Linux）

（v2.7.0 の要件定義書 §4 で対象外にした）

- GNOME の設定が無い・読めないときは、KDE の設定（`~/.config/kioslaverc`）を読む
- **手動**（`ProxyType=1`）なら、その中継先と除外を使う。**PAC**（`ProxyType=2`）は R-06 の処理系で評価する。自動検出・環境変数（`ProxyType=3`・`4`）の扱いは設計で決める
- 環境変数（`HTTPS_PROXY` など）があれば、それを先に使う（いまと同じ）

### R-04. PPTX に字体を埋め込む

（v2.7.0 の要件定義書 §5.2）

- 書き出した PPTX に、**スライドで使った字だけを抜き出した同梱フォント**（本文・太字・等幅）を埋め込む。同梱フォントが入っていない PC の PowerPoint でも、
  画面と同じ字体で出る
- 抜き出しは書き出すたびに行う（使った字が変われば中身も変わる）
- 字体のライセンス（SIL Open Font License 1.1）は埋め込みを許している。埋め込んだ字体に名前とライセンスの記載を残す
- 設定で埋め込みを切れる（既定は埋め込む）
- PowerPoint（Microsoft 365）で開けて、同梱フォントの入っていない PC でも同梱フォントで出ること。修復を求められないこと

### R-05. WYSIWYG で HTML の表を直す

（README の制限事項「WYSIWYG では、表のセルの結合・HTML で書いた表は直せない」。v2.5.1）

- 文書の中の **`<table>`〜`</table>` のブロック**を、プレビュー・WYSIWYG・PDF で**表として描く**（いまはプレビューで描いていない。`<img>` 以外の HTML のかたまりは描かないため）。
  `<thead>`・`<tbody>`・`<tr>`・`<th>`・`<td>` と、セルの結合（`colspan`・`rowspan`）、寄せ方（`align`・`style="text-align:…"`）を扱う。
  セルの中の字の飾り（`<b>`・`<i>`・`<code>`・`<a>`・`<br>`）は字の見た目として描く
- **それ以外の HTML（`<div>` など）はいまどおり**（プレビューでは描かず、HTML の書き出しでは原文を文字として出す。安全のため、任意の HTML は描かない）
- WYSIWYG では、HTML の表のセルの上で直接打つ（v2.5.1 の Markdown の表と同じ動き）。打った `<`・`&` は文字として逃がす（`&lt;`・`&amp;`）
- 行・列を足す／消すは、v2.5.1 の表の道具（帯のアイコン・編集 → 表）が HTML の表でも効く。結合したセルにまたがる行・列の足し消しは設計で決める
  （少なくとも原文を壊さないこと）
- 裏では原文の HTML を書き換え、**触っていないセル・タグ・属性・字下げは変えない**
- 読めない形の HTML の表（閉じていない・入れ子の表など）は、いまどおり原文のまま出す
- 設定で HTML の表を描かないこともできる（既定は描く）

### R-06. Linux の自動構成スクリプト（PAC）

（v2.7.0 の要件定義書 §5.2。v2.7.0 R-04 は GNOME の手動の設定だけ）

- Linux で、GNOME の設定が**自動**（`mode='auto'` と `autoconfig-url`）、または KDE の設定が PAC（R-03）なら、
  **PAC を取ってきて、組み込んだ JavaScript の処理系（boa）で評価**し、`FindProxyForURL` の答えの中継先を使う
- PAC が使う関数（`isPlainHostName`・`dnsDomainIs`・`shExpMatch`・`isInNet`・`dnsResolve`・`myIpAddress` など、PAC の決まりの関数）を用意する
- PAC は URL を開くたびに取り直さない（一度取ったものを覚えておく。覚える長さは設計で決める）
- PAC を取れない・評価に失敗した・時間がかかりすぎたときは、直接つなぐ（いまと同じ）。どの中継先を使ったかは、つなげなかったときの知らせに出す
- **Windows・macOS 版には処理系を入れない**（OS に任せたまま。§0.2）

### R-07. v2.7.0 の残りを直す

- 受入確認チェックリストの R-1〜R-4 の目視で見つかった不具合（あれば。PPTX の文字の折り返しや置き場所など）

## 2. 設定ファイルに足す項目と設定画面

`settings.toml` に足す。**読めない値は既定値**にする（いまと同じ）。名前と細かい値は設計で決める。
**どの項目も設定画面から変えられ、項目ごとに「既定」に戻せる**（v2.1.0 R-03 と同じ）。

|機能|項目|既定|設定画面の分類|
|---|---|---|---|
|色付け（R-01）|Markdown 以外のファイルに言語ごとの色を付けるか|付ける|エディタ|
|字体の埋め込み（R-04）|PPTX に字体を埋め込むか|埋め込む|スライド|
|HTML の表（R-05）|HTML の表を表として描くか|描く|プレビュー|

R-02（検索）・R-03（KDE）・R-06（Linux の PAC）は、いまの打鍵と設定（中継先を OS に聞く）を使い、項目は足さない。

## 6. 受け入れの確かめ方

v2.7.0 と同じく、単体試験と GUI 試験（`tools/automation/spec_test.py`）の項目を足し、受入確認チェックリストに目視の節を足す。

- HTML の表は、**直す前と後の原文を比べる試験**で、触っていないセル・タグ・属性が変わらないことを確かめる
- PPTX の字体は、書き出したものを**別の道具（python-pptx と fontTools）で読み直し**、埋め込んだ字体に使った字がそろっていることを台本で確かめる。
  同梱フォントの無い PC の PowerPoint で同じ字体で出ることは人が見る
- Linux の PAC は、PAC の決まりの関数と `FindProxyForURL` の答えを単体試験で確かめる（Linux の実機での確認は人が見る）
- macOS・Linux 向けのコードは、OS ごとのファイルを取り込んだ小さなクレートで clippy を通す（v2.7.0 と同じ）

締めに **release で組み、煙試験と `spec_test.py --perf`** を流す。

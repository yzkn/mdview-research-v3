## 1. 要件

### R-01. 文字を直せる PPTX の書き出し

（v2.4.0 R-07 では 1 枚 1 画像の PPTX にした。v2.4.0〜v2.6.0 の要件定義書 §5.2）

- Marp の文書を、**PowerPoint で文字を直せる PPTX** に書き出す。1 枚 1 画像の PPTX は無くす（§0.2）
- 1 枚のスライドの中身を、**ブロックごとの図形**にする

|ブロック|PPTX での形|
|---|---|
|見出し・段落|文字の箱。太字・斜体・取り消し線・インラインのコード・リンク（押せる）・字の色を保つ|
|リスト（番号・印・チェック）|文字の箱の段落の行頭記号と字下げ（入れ子の深さも）|
|引用|文字の箱と左の縦線|
|コードブロック|等幅の文字の箱と地の色（色付けした字の色も保つ）|
|表|PowerPoint の表（見出しの行・寄せ方）|
|図（Mermaid）・数式・画像|画像（描いた結果の PNG。手元の画像はそのまま）|
|背景の画像（`![bg]`）・背景の色|スライドの背景・図形の一番下の画像|
|ページ番号・ヘッダー・フッター|それぞれ文字の箱|
|発表者のメモ（`<!-- -->`）|ノート（いまと同じ）|

- **置き場所と大きさは画面の組み方から取る**（いまの PDF と同じ組み方で 1 枚を組み、ブロックごとの外枠を図形の枠にする）。
  折り返しは PowerPoint に任せるので、画面と少しずれうる。字が箱からはみ出しそうなときは、PowerPoint の「はみ出したら縮める」を入れる
- テーマ（`default`・`gaia`・`uncover`）の字の色・大きさ・地の色を、図形ごとの書式に写す（PowerPoint のテーマには写さない）
- `class: lead`・`invert` なども画面と同じ見た目の色・寄せ方にする
- 書き出しの窓・コマンドライン（`--export-pptx`）・MCP の書き出しのどれも、この形にする
- PowerPoint（Microsoft 365）で開けて、修復を求められないこと。LibreOffice Impress でも開けること

### R-02. TOML の frontmatter

（v2.6.0 の要件定義書 §4 で対象外にした）

- 文書の頭の `+++` で挟んだ TOML も、v2.6.0 R-03 の **frontmatter の欄**で見て直せるようにする
- 欄でできることは YAML と同じ（文字・数・真偽・日付の値と値の並びを直す、名前と値を足す・消す、入れ子の値（表 `[a]`・
  インラインの表）は原文の小窓）
- 裏では原文の TOML を書き換え、**触っていない行の書き方（引用符の種類・注釈・並び順）は変えない**
- 読めない TOML は欄を出さず、その旨を小さく出す（YAML と同じ）
- 欄を出している間は、プレビュー・WYSIWYG で TOML の frontmatter を本文として描かない（いまの YAML と同じ扱い。PDF・HTML は
  YAML と同じくいまのまま）。MCP の「構造」でも frontmatter として読む
- 表（`[名前]`・`[[名前]]`）は次の表までを 1 つの項目として原文の小窓で直す。項目は最初の表の前に足す（表の後ろに書くと
  その表の中身になるため）

### R-03. フォルダーの比較からまとめて写す

（v2.6.0 の要件定義書 §4 で対象外にした）

- フォルダーの比較の一覧で、**行を選んで（入れ切りの印。全部選ぶ・違うものだけ選ぶも）、左→右・右→左へまとめて写す**
- 写す先に無いファイルは作る（間のフォルダーも作る）。写す先にあるファイルは上書きする
- 写す前に、**作る・上書きする・消すの件数と一覧を見せて確かめる**
- **写す先にしか無いファイルを消す**（同期）は、確認の窓で利用者が選んだときだけ（既定は消さない）。消したものは
  **OS のごみ箱へ**入れる（ごみ箱が使えなければ消さずに知らせる）
- 写している間は進み具合を出し、画面を止めない。途中で止められる。写せなかったファイルは、終わってから一覧で知らせる
- 写し終えたら、写した行を比べ直す
- いま開いている窓の文書を上書きした場合は、その窓のいまの動き（外で書き換えられたら知らせる）に任せる

### R-04. macOS・Linux の PAC

（v2.6.0 の要件定義書 §5.2。v2.6.0 R-02 は Windows だけ）

- **macOS**: 中継先を OS に聞く（システム設定の手動の中継・自動構成スクリプト（PAC）・自動検出のどれでも、OS と同じ中継先を使う）
- **Linux**: GNOME の設定（`org.gnome.system.proxy`）が**手動**なら、その中継先と「中継しない所」を使う。**自動（PAC）**・設定が
  読めないときは直接つなぐ。JavaScript の処理系は入れない
- 環境変数（`HTTPS_PROXY` など）が設定されていれば、それを先に使う（いまと同じ）
- 設定「中継先（プロキシ）を OS に聞く」（v2.6.0）を macOS・Linux でも効かせる
- どの中継先を使ったかは、つなげなかったときの知らせに出す（いまと同じ）
- macOS は実機が無いので、組み立てと単体試験までで確かめる（README の「macOS 版は実機で見ていない」と同じ扱い）

## 2. 設定ファイルに足す項目と設定画面

`settings.toml` に足す。**読めない値は既定値**にする（いまと同じ）。名前と細かい値は設計で決める。
**どの項目も設定画面から変えられ、項目ごとに「既定」に戻せる**（v2.1.0 R-03 と同じ）。

|機能|項目|既定|設定画面の分類|
|---|---|---|---|
|まとめて写す（R-03）|写す前に確かめる|確かめる|比べる|

PPTX（R-01）・TOML（R-02）・PAC（R-04）は、いまの設定（書き出しの既定の形式・frontmatter の欄を出す・中継先を OS に聞く）を使い、
項目は足さない。

## 6. 受け入れの確かめ方

v2.6.0 と同じく、単体試験と GUI 試験（`tools/automation/spec_test.py`）の項目を足し、受入確認チェックリストに目視の節を足す。

- PPTX は、書き出したものを**別の道具（python-pptx）で読み直し**、スライドの枚数・図形の数・文字・表のセル・ノートが
  元の文書と合うことを台本で確かめる。PowerPoint・LibreOffice で開けることは人が見る
- TOML の frontmatter は、**直す前と後の原文を比べる試験**で、触っていない行が変わらないことを確かめる
- まとめて写すは、一時フォルダーで作る・上書き・消す（ごみ箱）の結果を確かめる

締めに **release で組み、煙試験と `spec_test.py --perf`** を流す。

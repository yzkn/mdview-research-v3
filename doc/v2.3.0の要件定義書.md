## 1. 要件

### R-01. 起動直後は窓を画面の中央に出す

- 設定「起動時のウィンドウの置き方」（v2.1.0 R-05）の**既定を「画面の中央」に変える**
- **すでに使っている人の設定は変えない。** 設定ファイルに `window_placement` が書かれていればその値に従う。
  書かれていない（初めて使う・項目が無い）ときだけ中央にする
- 中央の求め方は、いまの「画面の中央」と同じ（窓を出す前に置く。モニター全体の中央）。
  作業領域（タスクバーを除く）に合わせると、窓を出してから動かすことになり、起動時に窓が跳ぶ

### R-02. diff 表示

**2 つの文書を比べて、違いを色分けして出す。**

|項目|内容|
|---|---|
|比べるもの|① ファイルとファイル ② 編集中の文書と、保存してある元のファイル|
|開き方|メニューと打鍵から。ファイルは「アプリ内で開く」と OS のダイアログのどちらでも選べる|
|出し方|**左右に並べる（既定）**／**1 列に混ぜる**（行の頭に `+` / `-`）。設定と、表示中の切り替えの両方|
|比べ方の単位|行。変わった行の中は文字単位で比べる（下の b）|
|画面|**本文を覆う画面**（設定画面と同じ）。Esc で閉じる|
|左右の面|**どちらも直接書き換えられる**（D-1）。編集画面と同じ部品で、打鍵・選択・元に戻す・切り取りと貼り付け・書式の操作が使える。**検索は v2.3.0 では使えない**（検索バーは編集中の文書を相手にしている）|
|空きの行|片方にしか無い行の向かい側に、**書き込めない空きの段**を挟んで左右の高さを揃える|
|比べ直し|書き換えたら少し間を置いて（0.3 秒ほど）**裏の糸で**比べ直し、色と空きの行を更新する|
|左右の入れ替え|上の帯の「⇄ 左右を入れ替える」で入れ替える（D-4）。パッチの元（左）と新（右）も入れ替わる|
|1 列に混ぜる出し方|**読むだけ**（D-7）。書き換えるときは左右に並べる出し方へ切り替える|
|diff の画面で効かないもの|右端での折り返しと見出しの折りたたみ（左右の段の対応が崩れるため）。編集画面の設定は変えない。**編集中の文書を差し替える操作**（新規・開く・最近のファイル・ドロップ）と、検索・行へ移動・表示モードの切り替えも受け付けない|

WinMerge を参考にした追加機能（採用）:

|#|機能|中身|
|---|---|---|
|a|次の差分・前の差分へ飛ぶ|打鍵で差分から差分へ移る（既定は F7 / Shift+F7。§3）|
|b|行の中の差分を強調|変わった行の中で、変わった文字だけ色を濃くする|
|c|片側へ写す|選んだ差分を左から右へ（右から左へ）写す。写した側は未保存になる|
|d|比べ方の切り替え|空白・大文字小文字・改行コードの違いを無視する（それぞれ設定と表示中の切り替え）|
|e|差分の地図|横の細い帯に、差分のある場所を印で出す（ミニマップと同じ考え方）|
|f|左右のスクロールを揃える|片方を動かすと、もう片方も対応する行へついてくる|

- **10 MB 同士の比較は性能の目標に入れない。** 大きい文書では、比べ終わるまで待つ表示を出す（UI の糸を止めない）
- 差分の計算は **`similar` クレート**を使う（D-2。純 Rust・Apache-2.0）。パッチの書き出しと当てる処理は自前（context diff も扱うため）

保存（D-3・D-8・D-9）:

|比べるもの|左|右|
|---|---|---|
|① ファイルとファイル|書き換え・**保存できる**|書き換え・**保存できる**|
|② 保存してある元と編集中の文書|書き換え・右へ写すことはできるが、**保存はできない**（右と同じファイルのため）|**編集中の文書そのもの。** 直したところは閉じても編集画面に残る（未保存の印）|

- 保存していない側があるまま閉じようとしたら確かめる

### R-03. 差分からパッチを作る

- R-02 の差分を**パッチファイルに書き出す**
- 形式は **unified diff（既定）**／**context diff**（設定で切り替え）
- 前後に含める行数は 3 行（unified の既定と同じ）
- 改行コードは、比べた文書のものに合わせる
- **左を元、右を新**として書く（D-4。入れ替えれば逆になる）。見出しは GNU diff と同じく、ファイル名と更新日時（`--- memo.md` の後ろにタブと日時）。`a/`・`b/` は付けない

### R-04. パッチを開いて編集画面に当てる

- パッチファイルを選び、**編集中の文書に当てる**
- **当てた結果は編集中の文書に入れるだけ。** 保存は利用者に任せる（未保存の印が付く）。元に戻す（Ctrl+Z）で 1 回で戻せる
- **合わない hunk があっても、当てられる部分だけ当てる。** 合わなかった hunk の番号・行・中身を一覧で知らせる
- **unified と context の両方を読む。** 形式は中身から見分ける
- **行の位置がずれていても探して当てる。** ただし前後の行（context）が**完全に一致したときだけ**当てる（D-5。GNU patch の fuzz 0 と同じ）
- パッチに複数のファイルが入っているときは、**編集中の文書と同じ名前の部分**を当てる。1 つしか入っていなければそれを当てる。見分けがつかなければ選んでもらう（D-6）

### R-05. 好みの配色を指定する

- **いまのプリセット（明るい・暗い・iced の配色）は変えない。** その横に「自分の配色」を足す
- 利用者が変えられる部分:

|区分|色|
|---|---|
|全体|背景・文字・強調色|
|編集画面の記法|見出し・強調・コード・リンク・引用・リストの印|
|プレビュー|見出し・リンク・強調・コードの背景・コードの字句（6 色）・表の罫線・引用の線|
|**目 grep**|指定した文字列ごとに色を決め、出てきたところを**編集画面とプレビューの両方**で塗る。**ただの文字列か正規表現か**を文字列ごとに選ぶ（大文字小文字の区別も）|

- 色は **`#RRGGBB` で書く欄**にし、横に色見本を出す
- 自分の配色は、元にするプリセットを選んでから一部だけ変える形にする（全部を一から決めなくてよい）

決めたこと（2026-10-19。C-1〜C-5）:

|#|決めたこと|
|---|---|
|C-1|**編集画面の記法の色は v2.3.0 で新しく付ける**（v2.2 までの編集画面は 1 色）。**既定で付け**、設定で切れる（切れば 1 色）。色を付けるのは見えている行だけ|
|C-2|**自分の配色は、名前を付けていくつでも持てる**（R-06 で明るい時間と暗い時間に別々の配色を選ぶため）|
|C-3|**目 grep はいくつでも登録でき、それぞれオン・オフできる。** 色は登録した順に決まった色を回して振り、あとから変えられる。編集画面で選んでいる文字を、そのまま目 grep に足す操作も付ける|
|C-4|**目 grep の色は配色とは別に持つ**（配色を切り替えても同じ印）。半透明の地として塗る|
|C-5|**① 編集画面の記法の色 → ② 自分の配色 → ③ 目 grep** の順に作る|

### R-06. 日の出・日の入りで明るい・暗いを切り替える

- 配色の選択肢に「日の出・日の入りに合わせる」を足す
- 場所は**東京が既定**。**緯度・経度を設定で変えられる**（OS の位置情報は使わない）
- 時刻は**ネットにつながず計算で求める**（誤差 1〜2 分）。分単位の**オフセット（＋／−）**を日の出・日の入りそれぞれに付けられる
- **明るい時間と暗い時間に、それぞれどの配色を使うかを選べる**（プリセットと R-05 の自分の配色から）
- 起動中に時刻をまたいだら、その場で切り替える

### R-07. 列番号の表示

- **ルーラーと縦線の両方を入れ、それぞれ設定で表示／非表示を切り替える**
- (a) 編集画面の上に、桁を示す**目盛り（ルーラー）**を出す。キャレットの桁に印を付ける
- (b) **指定した桁に縦線**を引く（複数指定できる。例: 80, 120）
- 桁は表示上の幅で数える（全角は 2 桁、タブは `tab_width` で広げる）

### R-08. コードスニペットを入れる

- 入れ方: ① **メニューや一覧から選ぶ** ② **略語を打って Tab で広げる**（VS Code と同じ）
- **キャレットの直前の語が略語と一致したときだけ広げる。** それ以外は、いまの Tab（字下げ・表のセル移動）のまま
- 差し込み口（VS Code と同じ書き方）:

|口|中身|
|---|---|
|`$1` `$2` … `$0`|入力位置。Tab で順に移り、`$0` で終わる|
|`${1:既定の文字}`|既定の文字が選ばれた入力位置|
|`${date}` など|日付・時刻（書き方は設計で決める）|
|`${selection}`|入れる前に選んでいた文字|

### R-09. 設定画面でスニペットを決める

- 設定画面に「スニペット」の面を足し、**名前・略語・中身**を足す・直す・消す
- **初めから入れておくもの**: 表・コードブロック・Mermaid・数式・チェックリスト・リンク・画像・注記 など
- 初めからのものも直せる。消したものは「既定に戻す」で戻せる

### R-10. 目次を作る・作り直す（Markdown All in One 風）

- 「目次を入れる」で、キャレットの位置に `<!-- TOC -->` … `<!-- /TOC -->` を入れ、その中に見出しの一覧（リンク付き）を書く
- **保存のときに自動で作り直す**（印がある文書だけ）
- 入れる深さは**既定で 3 段目まで**（設定で変えられる）
- **見出しに番号（1.1 など）を振る機能**も入れる。振る・外すの操作。**番号を振った文書は、保存のたびに振り直す**
- コードブロックの中の `#` は見出しとして扱わない

### R-11. Markdown の検査（linter）

- markdownlint の規則（MD001 など）のうち、**よく使うものを自前で作る**（規則の一覧は設計で決める）
- 出し方: **編集画面に波線**と、**一覧の窓**の両方。一覧から行へ飛べる
- **その場で直す機能（クイックフィックス）**を、直し方が 1 つに決まる規則に付ける
- **規則ごとにオン・オフ**を設定できる
- 大きい文書では、見えている範囲から順に検査する（UI の糸を止めない）

### R-12. Fluent Design を考えた光と影の UI

- 浮き上がる面（ダイアログ・メニュー・一覧）に**影**を付け、操作できる部品に**光の当たり方**（ホバー・押下の明るさ）を付ける
- **設定画面・About・文字コード・検索・確認・ファイル選択（アプリ内で開く）**のダイアログの外観を共通の部品にそろえる。OS のファイルダイアログはそのまま
- 透明感（Mica・Acrylic）は v2.4.0（§5.1）

### R-13. 集中モード

- **全画面にし、メニュー・ステータスバー・目次・ミニマップなどを隠して本文だけにする**（すべての OS）
- 入る・出るは打鍵とメニューから。Esc でも出られる
- 表示モード（編集・分割・プレビュー）はそのまま使う
- **OS の通知は扱わない。** Windows の「応答不可」と macOS の「集中モード」は、アプリから入れる公開された手段が無い（§4）

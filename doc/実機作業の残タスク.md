## 0. この表の考え方

CI が確かめられるのは「組み立てられること」と「自動試験が通ること」だけである
（基本設計書 §27.5）。残るのは次の 2 種類で、**どちらも人の手が要る**。

|種類|中身|
|---|---|
|**実機**|画面を見ないと分からないもの（字形・IME・描画）|
|**計測**|数値を取るもの（起動時間・打鍵・fps・メモリ）|

何を見るかは [受入確認チェックリスト](受入確認チェックリスト.md) にある。
**この表はそのうち「まだ済んでいないもの」だけ**を追う。

## R-01 10MB での計測

**目的**: 基本設計書 §20 の実測欄を v2 の数値で埋める。

**なぜ手作業か**: runner に GPU が無く、性能も一定でない（§27.5）。

### 取るもの

|項目|目標|受入条件|
|---|---|---|
|起動〜初回描画|2 秒以内|§20.3|
|1 打鍵|16.6ms 以内|§20.2 / A2-01|
|スクロール|60fps|A2-02|
|メモリ|§20.1 の目標以下|A2-05|

### 手順

```powershell
# 起動時間（中央値を取る）
.\measure-startup.ps1

# スクロール
.\measure-scroll.ps1
```

**単発の計測を根拠にしない**（DD-OPEN-07）。Edit のみで 17% 振れた例がある。

## R-02 出力の性能計測

v1 の計測（300KB で 10.70 秒）は **WebView2 の印刷エンジン**に対するもので、
v2 は krilla で自前に組むため数値が変わる。取り直す。

|文書の大きさ|取るもの|
|---|---|
|100KB|PDF / HTML それぞれの所要|
|300KB|同上|
|10MB|同上（**途中で取り消せること**も見る。§17.10）|

## R-04 / R-05 実機の無い OS

**実機が手に入るまで未確認のまま配る。**
配るときに「見た人がいない版」であることを伝える
（[リリース手順](リリース手順.md) §5）。

手順は [macOS作業手順](macOS作業手順.md) にある。Linux も同じ考え方で、
`.deb` か AppImage を入れて [受入確認チェックリスト](受入確認チェックリスト.md)
の実機項目を実施する。

### Linux は WSLg で一部を埋められる（2026-10-05）

この端末の WSLg（Windows 上の Linux GUI）で、**字形・レイアウト・図・数式・
`.deb` の導入と削除**までは見られる。手順は
[Linux版をWSLgで確認する](Linux版をWSLgで確認する.md)。

**埋まらないものを先に書いておく。**

|埋まらないもの|理由|
|---|---|
|**性能（A2-02）**|dzn の ICD が無く、Vulkan は lavapipe（ソフトウェア描画）になる|
|**IME（A2-04）**|WSLg に IME が無い|
|ネイティブ GPU ドライバ・デスクトップ統合|実ドライバもデスクトップシェルも通らない|

**「Linux 実機で確認した」とは書けない。** 書き方は手順書 §4 に定めた。

macOS は WSLg では代替できない。

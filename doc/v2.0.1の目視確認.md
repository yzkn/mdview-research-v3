## A. スクロールバー（D-19 / D-20）

```powershell
.\target\release\mdview.exe samples\check-v201.md
```

### A-1 出ること

|見るところ|正しい状態|
|---|---|
|エディタの**右端**|縦のつまみが出ている|
|エディタの**下端**|横のつまみが出ている（長い行があるため）|
|プレビューの**右端**|縦のつまみが出ている|

> **つまみは本文に重ねて描いてある。** 本文の幅は削っていないので、
> 文字の上に半透明の帯が乗る。これは意図したものである。

### A-2 長さと位置が中身に合っていること

- 先頭では**上端**、末尾（`Ctrl + End`）では**下端**に着く
- 窓を広げるとつまみが**長く**なる（見えている割合が増えるため）
- **短い文書ではバーが出ない。** `samples\sample.md` を開いて確かめる
  （動かせないものを出さない方針）

### A-3 掴んで動かせること

|操作|起きること|
|---|---|
|つまみを**掴んで上下**|本文が付いてくる。**掴んだ瞬間に飛ばない**|
|つまみの**外側の溝を押す**|つまみの中心がそこへ来る（その位置へ飛ぶ）|
|掴んだまま**窓の外まで動かす**|端で止まる。離すまで掴んだままになる|
|横のつまみを掴む|本文が横に動く|

### A-4 マウスカーソルの形

|どこ|形|
|---|---|
|つまみ・溝の上|**掴める形**（手のひら）|
|掴んでいる間|**掴んだ形。** 軌道の外へ出ても変わらない|
|本文の上|I ビーム（従来どおり）|
|バーを出していない短い文書|**変わらない**（何も無いのに押せそうに見せない）|

### A-5 下まで巻き上げられること（**直したところ**）

**文書を開いた直後、キャレットは先頭に居る。** その状態のまま
ホイールで下まで送れることを見る。

|操作|正しい状態|
|---|---|
|開いた直後にホイールで下まで送る|**末尾まで行く。** 途中で先頭へ戻らない|
|つまみが下端に着いたあともホイールを回す|**それ以上動かない**（文書が画面から出ていかない）|
|そのあと矢印キーを押す|キャレットの位置まで**戻る**（これは正しい動き）|

> 直す前は、キャレット追従が毎回働いて**巻き上げを巻き戻していた**。
> 「少し送れるがすぐ先頭へ帰る」という挙動になる。

### A-6 スクロール同期（**直したところ**）

**分割表示で、同期を入れた状態で見る**（表示メニュー →「スクロール同期」）。

|操作|正しい状態|
|---|---|
|エディタのつまみを掴んで動かす|**プレビューも付いてくる**|
|エディタの溝を押して飛ばす|同じく付いてくる|
|巻き上げてから矢印キーを押す|キャレットへ戻り、**プレビューも付いてくる**|
|巻き上げてから文字を打つ|同じく付いてくる|
|ホイールで動かす|付いてくる（もともと効いていた）|
|**同期を切る**|エディタだけ動き、**プレビューは動かない**|

> 直す前は、**つまみと矢印キーの 2 つだけ**が取り残されていた。
> ホイールでは効いていたので、気づきにくい形だった。

### A-7 画面の外に長い行があるときの横送り（**直したところ**）

確認用文書の **16 行目と 19 行目**が折り返さない長い行である。

|操作|正しい状態|
|---|---|
|長い行が見えている状態で横へ動かす|動く|
|**長い行から下へ大きく離れて**横へ動かす|**動く**（バーが消えない）|
|末尾（`Ctrl + End`）まで行ってから横へ|同じく動く|

> 直す前は、可視範囲の行しか測っていなかったため、**長い行から縦に
> 離れるとバーが消えて横へ動けなかった。**
>
> **横へ動ける量は目安である。** 文書が覚えている「いちばん長い行」は
> バイト数で選んでいるため、実際の幅と少しずれることがある。
> 見えている行については正しく測るので、読むのに困ることはない。

### A-8 他の操作を邪魔しないこと

- バーの**上で押しても文字が選択されない**（選択より先に受ける）
- バーの**外で押せば今までどおり選択できる**
- **長い行の右端の三角**（続きがある印）が、縦のバーと重なっていない

## B. タッチパッドの二本指（D-21）

**これが今回の本題である。** 直す前は、横にわずかに揺れるだけで
縦に動かなくなっていた。

|操作|正しい状態|
|---|---|
|二本指で**まっすぐ上下**|縦に動く|
|二本指で**斜めに**動かす|**縦にも横にも動く。** 縦が止まらない|
|二本指で**ゆっくり**上下|少しずつでも必ず動く（端数を繰り越す）|
|`Shift` を押しながら縦に回す|**横に**動く（縦には動かない）|
|マウスのホイール|今までどおり縦に動く|

エディタとプレビューの**両方**で見る。

> **斜めが肝心である。** まっすぐ縦に動かせてしまうと、直す前の版でも
> 動いてしまう。指を少し斜めに流して確かめる。

## C. 自前のファイル選択（B-0）

### C-1 Windows で先に形を見る

OS のダイアログが使える環境でも、**メニューから呼べる**。

```
ファイル → アプリ内で開く…    （または Alt+F → I）
```

強制的に自前のものにしたいときは次のようにする。この場合、
`Ctrl + O` や「開く…」も自前のものになる。

```powershell
$env:MDVIEW_IN_APP_PICKER = "1"
.\target\release\mdview.exe samples\check-v201.md
```

|操作|正しい状態|
|---|---|
|開いた直後|**いま開いている文書の置き場**が出ている|
|`↑` `↓`|選択が動く。**端で止まる**（巻き戻らない）|
|`PageUp` `PageDown`|10 件ずつ動く|
|フォルダで `Enter`|中へ入る。**閉じない**|
|「上へ」／`Backspace`|1 つ上へ|
|ファイルで `Enter`|**閉じて、その文書が開く**|
|一覧を 1 回押す|選ぶだけ|
|選んでいるものをもう 1 回押す|決まる|
|欄にパスを打って `Enter`|そのファイルが開く|
|**無い名前**を打って `Enter`|**閉じずに「見つかりません」**が出る|
|`Esc` ／「取り消し」|閉じる。**そのあとファイル操作が普通にできる**|

> **最後の 1 行が大事である。** 閉じ損ねると以後なにも開けなくなる。
> 取り消したあと、もう一度 `Ctrl + O` が効くことを必ず見る。

**`.md` 以外は一覧に出ない**（絞り込み）。フォルダは絞り込まない。
絞り込みの外にあるものは、欄にパスを打てば開ける。

### C-2 WSL で確かめる（本題）

**これが v2.0.1 で直した当のものである。** 直す前は WSL で
`Ctrl + O` を押しても何も起きなかった。

Linux の配布物が要る。手順は
[Linux版をWSLgで確認する](Linux版をWSLgで確認する.md) を参照。

```bash
XDG_RUNTIME_DIR=/mnt/wslg/runtime-dir ~/mdview-2.0.1/usr/bin/mdview ~/check-v201.md
```

**直す前と見比べられるようにしてある。** v2.0.0 を `~/mdview-2.0.0` に
展開したままにしてあるので、同じ操作を両方で行えば違いが分かる。

```bash
# 直す前（押しても何も起きない）
XDG_RUNTIME_DIR=/mnt/wslg/runtime-dir ~/mdview-2.0.0/usr/bin/mdview ~/check-v201.md
```

確認用の文書は `~/check-v201.md` に置いてある。

|操作|正しい状態|
|---|---|
|`Ctrl + O`|**自前の選択が出る**（直す前は無反応）|
|ファイルを選ぶ|開ける|

> **WSL には D-Bus も xdg-desktop-portal も無い。** そのため
> `os_dialog_available()` が偽を返し、自動で自前のものに切り替わる。
> 切り替わらなければ、判定が効いていないということである。

# 起動制御機能 仕様書

> **当面実装しない**（2026-10-16 決定）。本書は仕様の記録として残すが、mdview にはこの機能を
> 入れていない。実装するときは改めて判断する（基本設計書 §3.2・詳細設計書 §11 の DD-OPEN-17）。

## 1. 目的

特定の設定値が未設定である場合に限り、ログオンユーザー名に特定文字列を含むユーザーによるアプリケーション起動を抑止する。

本機能の目的はセキュリティ対策ではなく運用制御である。

そのため、

- 判定条件をユーザーに明示しない
- ユーザー名が原因であることを推測しづらくする
- Windows / macOS / Linux を同一実装方針でサポートする

ことを重視する。

---

# 2. 要件

## 起動制御条件

以下の条件をすべて満たす場合、アプリケーションを起動させない。

### 条件1

設定ファイルに対象設定値が存在しない。

または、

```toml
ignore_validation = false
```

が設定されている。

### 条件2

ログオンユーザー名が禁止文字列を含む。

禁止文字列:

```text
###
```

例:

```text
user###test
```

→ 起動拒否

---

# 3. 判定方式

## 比較方法

大文字小文字は区別しない。

判定前にユーザー名を Unicode Lowercase 化する。

例:

```text
ABC###XYZ
↓
abc###xyz
```

---

## マッチ方式

部分一致とする。

Rust においては以下と同等。

```rust
username.contains(pattern)
```

例:

```text
pattern = "###"
```

の場合

```text
user###test
```

→ NG

```text
###user
```

→ NG

```text
user###
```

→ NG

```text
user
```

→ OK

# 6. 起動拒否時の動作

## 要件

ユーザーに以下を推測させない。

- ユーザー名
- 判定文字列
- 設定値
- 起動拒否ロジック

---

## 表示メッセージ

以下の固定メッセージを表示する。

```text
アプリケーションの初期化に失敗しました。
```

---

## 禁止事項

以下のようなメッセージは禁止とする。

```text
ユーザー名が許可されていません
```

```text
開発者アカウントでは起動できません
```

```text
###を含むユーザーでは起動できません
```

- Windows対応
- macOS対応
- Linux対応
- 外部プロセス起動禁止
- 単一実行ファイル構成維持
- 判定処理は100ms未満を目標
- iced初期化前に完了すること
- ユーザー名取得失敗時は起動継続（フェイルオープン）
- 設定ファイル解析失敗時は起動制御有効（フェイルセーフ）

### platform/windows.rs

```rust
use anyhow::{anyhow, Result};
use windows::core::PWSTR;
use windows::Win32::Security::Credentials::GetUserNameW;

pub fn current_username() -> Result<String> {
    let mut buf = [0u16; 256];
    let mut len = buf.len() as u32;

    unsafe {
        GetUserNameW(PWSTR(buf.as_mut_ptr()), &mut len)
            .map_err(|e| anyhow!("{e}"))?;
    }

    Ok(
        String::from_utf16_lossy(
            &buf[..(len as usize - 1)],
        )
    )
}
```

---

### platform/macos.rs

```rust
use anyhow::{anyhow, Result};
use std::ffi::CStr;

pub fn current_username() -> Result<String> {
    unsafe {
        let uid = libc::getuid();
        let passwd = libc::getpwuid(uid);

        if passwd.is_null() {
            return Err(anyhow!("getpwuid failed"));
        }

        let name = CStr::from_ptr((*passwd).pw_name);

        Ok(name.to_string_lossy().to_string())
    }
}
```

## A-3. 起動制御実装

### startup_policy.rs

```rust
use anyhow::{bail, Result};

use crate::config::Config;
use crate::platform::current_username;

/// 起動制御対象文字列
const BLOCK_PATTERNS: &[&str] = &[
    "###",
];

pub fn validate_startup(
    config: &Config,
) -> Result<()> {

    let ignore_validation =
        config.ignore_validation.unwrap_or(false);

    if ignore_validation {
        return Ok(());
    }

    let username = match current_username() {
        Ok(name) => name.to_lowercase(),
        Err(_) => {
            // ユーザー名取得失敗時はフェイルオープン
            return Ok(());
        }
    };

    let matched =
        BLOCK_PATTERNS
            .iter()
            .any(|pattern| {
                username.contains(
                    &pattern.to_lowercase()
                )
            });

    if matched {

        #[cfg(debug_assertions)]
        eprintln!("Startup restriction matched.");

        bail!("startup blocked");
    }

    Ok(())
}
```

## A-4. main.rs組み込み例

```rust
fn main() {

    let config = load_config();

    if let Err(_) =
        startup_policy::validate_startup(&config)
    {
        eprintln!(
            "アプリケーションの初期化に失敗しました。"
        );

        std::process::exit(1);
    }

    run_application();
}
```

## A-8. 実装方針まとめ

- Windows/macOS/Linux対応
- ユーザー名はOS APIから取得
- 環境変数 USERNAME は使用しない
- 禁止文字列は startup_policy.rs 内の定数として保持
- ignore_validation=true の場合のみ判定を無効化
- 未設定は判定有効
- ユーザー名取得失敗時は起動継続
- 利用者へは「アプリケーションの初期化に失敗しました。」のみ表示
- ユーザー名や判定条件は画面表示しない
- 単一実行ファイル構成を維持する
- iced初期化前に判定する

作成日: 2026-10-20
対象: mdview v2.4.0（v2.3.0 の次の機能追加版）

## 0. この文書の位置づけ

v2.4.0 で入れる機能を決める。**何を・どこまで作るか**を書き、作り方は
詳細設計書 §10 の経緯欄（§10.67 以降）に残す。

要件は利用者が挙げたもの（2026-10-19・2026-10-20）。v2.3.0 の要件定義書 §5.1 で聞き取った
3 つ（WYSIWYG 編集・Marp の資料作成支援・Fluent Design の透明感）に、背景画像・MCP サーバーと、
MarkUpsideDown（[開発マニフェスト](https://zenn.dev/jphfa/articles/markupsidedown-development-manifesto)）から
採った 3 つを足した。

> 背景画像の参考に挙げられた記事（[zenn.dev/tris](https://zenn.dev/tris/articles/e60efe7c60a770)）は、
> iced 0.3 で作る画像ビューア（落とした画像を `Image` で縮尺を合わせて出す）の記事で、背景画像の機能そのものの
> 記述は無い。iced で画像を出す作り方の参考として扱う。要件は利用者への聞き取りで決めた。

## 1. 要件

### R-01. 背景画像を設定・表示する

**好きな画像を本文の後ろに敷く。** 文字を読みやすく保つため、透明度とぼかしを決められる。

|項目|内容|
|---|---|
|敷く所|**既定は編集画面とプレビュー**（それぞれの領域に 1 枚ずつ）。設定で選ぶ: 窓全体（メニュー・目次・ステータスバーを含む）・編集画面だけ・プレビューだけ・**分割表示の 2 つの領域にまたがって 1 枚**|
|画像ファイル|設定画面で選ぶ（OS のダイアログとアプリ内のファイル選択）。形式はプレビューで出せる画像と同じ（PNG・JPEG など。設計で決める）|
|表示方法|**並べる**（繰り返す）・**伸ばす**（縦横比を保たない）・**全体を収める**（縦横比を保ち、全体が入る）・**覆う**（縦横比を保ち、隙間なく覆う。はみ出しは切る）・**原寸で置く**|
|置く位置|9 か所（左上・上・右上・左・中央・右・左下・下・右下）。並べる・伸ばす以外で効く|
|透明度|0〜100%。**既定は文字が読める薄さ**（設計で決める）|
|ぼかし|強さを選ぶ（無し・弱・中・強など）。**描くたびにはぼかさない**（読み込んだときに 1 度だけ作る）|
|動き方|**既定は窓に固定**（本文を送っても背景は動かない）。設定で**本文と一緒に動かす**こともできる|
|明るい・暗い|**配色が明るいときと暗いときで、別の画像・透明度・ぼかし**を決められる（v2.3.0 の日の出・日の入りの切り替えにも従う）|
|出力|PDF・HTML には入れない（画面だけの飾り）|
|消す|設定で「背景画像を使わない」に戻せる。ファイルが見つからないときは敷かずに、設定画面にその旨を出す|
|設定画面|「外観」に「背景画像」の欄。使う・使わない、明るい配色・暗い配色ごとの画像・表示方法・位置・透明度・ぼかし、敷く所・動き方。**見本を小さく出す**|

- 大きい画像は読み込むときに画面の大きさへ縮めて持つ（描く負担とメモリを抑える）
- 背景画像を敷いた所では、地の色の代わりに画像を描き、その上に文字を描く。選択・検索の一致・差分の色は今のまま重ねる

### R-02. コマンドパレット

- **Ctrl+Shift+P** で開く。メニューにある操作（キー割り当ての対象と同じ一覧）を、**名前を打って絞り込み、Enter で実行**する
- 一覧には**割り当てた打鍵を並べて出す**（覚える助けにする）
- いま使えない操作は、薄く出して実行できないようにする（メニューと同じ判断）
- 絞り込みは部分一致（ひらがな・カタカナ・大文字小文字の違いを無視する。細かい決まりは設計で）。**最近使った操作を上に出す**
- Esc で閉じる。打鍵はキー割り当てで変えられる

### R-03. プレビューから編集の行へ・キャレットを追う

- **プレビューの段落・見出し・表・コードブロックを押すと、編集画面のその行へ飛ぶ**（分割表示のとき。プレビューだけのときは編集画面に切り替えて飛ぶ）
- **押し方の既定はダブルクリック**（押して引くのは今までどおり文字の選択）。設定で **Alt + クリック・Ctrl + クリック**にも変えられる。
  Ctrl + クリックにしたときも、リンクの上ではリンクを開く（v2.1.0 R-19）を優先する
- **キャレットを動かすと、プレビューもその位置が見えるように送る**（スクロール同期を入れているとき）
- コードブロックの中は、押した所の行まで追う
- リンクを押したとき（v2.1.0 R-19）は今のまま
- **設定で切れる**: 「プレビューから編集の行へ飛ぶ」（既定は使う）と、「キャレットを追ってプレビューを送る」（既定は使う）を
  それぞれオン・オフ。設定画面の「プレビュー」に欄（押し方の選択を含む）

### R-04. 図の拡大・移動・PNG で写す

- **プレビューの図（Mermaid）・数式のブロック・画像（`![]()`・`<img>`）を、拡大して見る画面**を出す（本文を覆う。Esc で閉じる）
- その画面では、**ホイール（または Ctrl+ホイール）で拡大・縮小**、**引いて動かす**、**等倍・全体を収める**に戻す
- **PNG としてクリップボードへ写す**（拡大して見ている倍率ではなく、決まった解像度で。設計で決める）。PNG のファイルにも保存できる
- 開き方: **図の上にホバーで出る小さなボタン**と、図のダブルクリック（R-03 の押し方と重なるときは、図の上では拡大を優先する）。細かい形は設計で決める
- **設定で切れる**: 「図を拡大して見る」（既定は使う）・「図の上にボタンを出す」（既定は出す）・写す PNG の倍率（既定 2 倍）。
  設定画面の「プレビュー」に欄

#### R-04 b. コードブロックをクリップボードへ写す（2026-10-20 に足した）

- **プレビューのコードブロックの右上に、ポインタを置くと「コピー」のボタンを出す**（図の拡大のボタンと同じ出し方）。
  押すと**コードの中身**（前後の ``` の行を除いた本文）を文字としてクリップボードへ写し、写したことを知らせる
- 図として描くコードブロック（Mermaid・数式）は、図の拡大（R-04）を出す
- **設定で切れる**: 「コードブロックにコピーのボタンを出す」（既定は出す）。設定画面の「プレビュー」に欄

### R-05. Fluent Design の透明感（Mica 風）

> **2026-10-20 に変えた。** iced 0.14 は Windows で DX12 の描画先を不透明でしか作らない（wgpu の DirectComposition の
> 口を通さない）ため、窓を透かす本物の Mica・Acrylic は出せない。**Mica の見た目（デスクトップの壁紙を強くぼかし、
> 配色の色を薄く重ねた地）を自前で描く**（利用者の判断）。後ろのほかの窓が透けて見える Acrylic は扱わない（§4）

- **Windows では、窓の地にデスクトップの壁紙を強くぼかして敷き、配色の地の色を重ねる**（Mica 風）。
  壁紙は OS から読み、**窓の画面上の位置に合わせてずらす**（窓を動かすと、壁紙のその部分が見える）
- 壁紙が読めない（単色・スライドショーで読めないなど）ときは、いままでの不透明な地のまま
- ほかの OS は不透明のまま（macOS・Linux は v2.4.0 では扱わない）
- 文字の読みやすさを保つため、本文の領域には薄い地を残す
- **設定で選ぶ**: 「透明感」を Mica 風（既定）・不透明から。「本文の地を残す」（既定は残す）をオン・オフ。
  設定画面の「外観」に欄（Windows 以外では欄を薄くし、効かないことを書く）
- 背景画像（R-01）を敷いた所は背景画像を優先する

### R-06. MCP サーバー

**Claude などの MCP クライアントから、mdview の機能を「意味のある操作」として呼べるようにする**
（画面のボタンを押させるのではなく、文書の構造を取る・見出しを直す、などを直接呼ぶ）。

#### 動き方

|場面|動き|
|---|---|
|窓が開いている|**その窓につなぐ。** 本文の読み書きはその場で画面に出る。書き換えは**元に戻すで 1 回で戻る**。窓が複数あれば、どの窓かを選べる（窓の一覧の操作）|
|窓が開いていない|**窓を出さずに動く。** ファイルを読み、検査・比較・出力などをする|
|「確認」にした操作を、窓が無いときに呼ばれた|**そのときだけ確認の窓を出し**、利用者の答えを待つ|

#### つなぎ方

- **stdio**: クライアントが `mdview --mcp` を起こし、標準入出力で話す（Claude Desktop・Claude Code など）。
  開いている窓とは、手元だけの通り道（名前付きパイプ・UNIX ソケットなど。設計で決める）でつなぐ
- **手元の HTTP**（Streamable HTTP）: **既定は閉じる。** 開いたときは **127.0.0.1 だけ**で受け、**起動ごとに作る合言葉（トークン）**を求める
  （設定画面に出し、写せるようにする）。待ち受ける番号（ポート）は設定で変えられる
- ネットの外へは何も送らない（mdview の「ネットにつながなくても全機能が使える」を保つ）

#### 許す操作

- **既定は、壊しうる操作（下の表）が「確認」、それ以外は「許可」。** 設定画面（新しい分類「MCP」）で、
  **操作ごとに「許可」「確認」「拒否」**を選べる

|既定が「確認」の操作|理由|
|---|---|
|上書き保存・名前を付けて保存・PDF に出力・HTML に出力・パッチを当ててファイルに書くなど、**ディスクのファイルを作る・書き換える**もの|ファイルが書き換わる|
|**自動保存（v2.1.0 R-22）を入れている窓での、本文を書き換える操作すべて**（範囲を置き換える・入れる・置き換え・検査の「直す」・目次・番号など）|書き換えたあと N 秒で自動でファイルに書かれ、実質ファイルを書く操作になる。**窓ごとに、その時点の自動保存の有無で決める**|
|全文を置き換える|元に戻すで戻せるが、文書を丸ごと入れ替えるので、気づかずに続けて打つと戻しにくい|
|すべて置き換える（正規表現を含む）|一度に多くの箇所が変わり、意図しない一致まで変えやすい|
|パッチを窓の本文へ当てる|多くの行が一度に変わる。合わなかった部分だけが残り、結果が分かりにくい|
|開いている窓でほかのファイルを開く|未保存の変更が失われる|
|読み直す・保存してある内容に戻す|未保存の変更を捨てる|
|窓を閉じる・アプリを終える|未保存の変更を捨てうる|
|リンクを開く（OS の既定のアプリ・ブラウザーで）|外のプログラムを起こす。悪意のある文書のリンクを開くと、知らないファイルやサイトが開く|
|設定を変える|外観・キー割り当てなどが、ほかの窓にも効いて変わる|
|読み取り専用を外す|読み取り専用にした意味が無くなる|
|クリップボードへ写す（図の PNG など）|利用者がクリップボードに入れていたものが上書きされる|

- 上の表に無い、窓の中の本文を書き換えるだけの操作（自動保存を入れていない窓。保存しない）は「許可」。元に戻すで戻せるため
- 「確認」は、呼ばれるたびに画面で「AI が〇〇をしようとしています」と出し、利用者が許したときだけ行う
- 「拒否」は、理由をつけて断る（クライアントに返す）
- 何を呼ばれたかを、窓の中の記録（一覧）で見られるようにする（設計で決める）

#### 設定画面

新しい分類「**MCP**」を置く。

|欄|中身|
|---|---|
|MCP サーバーを使う|オン・オフ（**既定はオン**。オフのときは `mdview --mcp` で起こされても、つながずに理由を返して終わる）|
|窓が無いときも受ける|オン・オフ（既定はオン）|
|手元の HTTP|開く・閉じる（既定は閉じる）・ポート・合言葉（出す・写す・作り直す）|
|操作ごとの扱い|操作の一覧に「許可」「確認」「拒否」を選ぶ欄。**既定に戻す**（1 件ずつ・すべて）。既定と違うものに印|
|呼ばれた記録|最近の呼び出し（いつ・どの操作・扱い・結果）|
|クライアントの設定の例|Claude Desktop・Claude Code に書く設定の例を出し、写せるようにする|
|注意|ファイルを読む操作の注意（下の注意書きと同じ）|

#### 出す操作

|分類|操作|
|---|---|
|窓|開いている窓の一覧・窓を選ぶ・ファイルを開く（新しい窓）・**開いている窓でほかのファイルを開く**・**窓を閉じる**・**アプリを終える**|
|本文|全文を取る・範囲を取る・選んでいる所を取る・範囲を置き換える・入れる・全文を置き換える・**読み直す（保存してある内容に戻す）**|
|構造|見出し・リンク・表・リスト・frontmatter・統計（行数・文字数）を JSON で取る（v2.3.0 の目次・検査と同じ読み方）|
|検索|探す・置き換える（正規表現を含む）|
|検査|Markdown の検査の結果を取る・直す（v2.3.0 R-11）|
|整える|目次を入れる・作り直す、見出しの番号を振る・外す（v2.3.0 R-10）、表を整える|
|比べる|2 つの文書・ファイルを比べる、パッチを作る・当てる（v2.3.0 R-02〜R-04）|
|保存・出力|上書き保存・名前を付けて保存・PDF・HTML に出力・**クリップボードへ写す**（図の PNG など）|
|そのほか|**リンクを開く**（OS の既定のアプリ・ブラウザー）・**設定を変える**・**読み取り専用を切り替える**|

- 書き換える操作はすべて、読み取り専用（v2.1.3）の窓では断る（読み取り専用を外す操作は別。既定は「確認」）
- ファイルを読む・書く操作の置き場の制限は設けない。書く操作は既定で「確認」なので、利用者が置き場を見て判断する。
  読むことも止めたければ「確認」か「拒否」にする
- > **注意: ファイルを読む操作は既定で「許可」。** 壊しはしないが、置き場を絞らないので、**どのファイルでも
  > 中身を AI（MCP クライアント）へ渡せる**（機密のファイルを含む）。気になる場合は、読む操作を「確認」か「拒否」にする。
  > 設定画面の MCP の分類と、使い方の文書にもこの注意を出す

### R-07. Marp の資料作成支援

（v2.3.0 の要件定義書 §5.1 で聞き取ったもの）

- **スライドに分けたプレビュー**（`---` で区切る。Marp の文書（frontmatter に `marp: true`）のとき）
- **Marp の指示（`theme`・`paginate`・`header`・`footer`・`class` など）を補う**（入力の候補・検査）
- **PDF・HTML・PPTX への書き出し**（PPTX は **1 枚 1 画像で貼ったもの**。Marp CLI と同じで、PowerPoint で文字は直せない）
- **発表用の全画面表示**（1 枚ずつ。矢印・PageUp/PageDown・Space で送る。Esc で終わる）
- 外部のプログラム（Node.js・Marp CLI）は使わない（単一の実行ファイルのまま）。テーマは Marp の
  `default`・`gaia`・`uncover` に近いものを持つ（設計で決める）
- **設定で切れる**: 「Marp の文書をスライドに分けて見せる」（既定は使う。切ると普通の Markdown として見せる）・
  「Marp の指示を補う」（既定は使う）・発表のときに**ページ番号と経過時間を出す**（既定は出さない）。
  設定画面に新しい分類「**スライド**」を置く（書き出しの既定の形式も選ぶ）

### R-08. WYSIWYG 編集

（v2.3.0 の要件定義書 §5.1 で聞き取ったもの）

- 編集・分割・プレビューに加えて **4 つ目の表示モード**
- **文字・表・リスト・見出しの組み替え・図や数式まで**、描いた結果の上で直接書き換える
- 保存するのは Markdown のまま。書き戻すときは、元の書き方（`*` と `-`、`**` と `__` など）を**できるだけ保つ**。
  触った所だけ、決まった書き方（設定の既定）で書く
- **10 MB の文書で動く必要はない**（大きい文書では、このモードに入れない・知らせる。上限は設計で決める）
- 元に戻す・やり直しは、ほかの表示モードと同じ履歴を使う
- **設定で選ぶ**: 「WYSIWYG を使う」（既定は使う。切ると表示メニューと切り替えから外す）・新しく書くときの記法
  （リストの印 `-`／`*`、強調 `*`／`_`、太字 `**`／`__`、見出し `#`）・このモードに入れる文書の大きさの上限（既定は設計で決める）。
  設定画面の「エディタ」に欄

---

### R-09. URL を開く（2026-10-21 に足した）

（利用者の要望。R-07 を作っている途中で挙がった）

- **ファイル → URL を開く…（Ctrl+Shift+L）**で、URL を打って Markdown を開く。最近開いた URL を窓に並べ、選んで開ける
- 開いた文書は**読み取り専用**で、保存先を持たない（直して残すときは、読み取り専用を外して「名前を付けて保存」）
- 読めるのは `http://` と `https://` だけ。大きすぎるもの（20 MB 超）は読まない。証明書は OS の確かめ方に任せる。
  中継（プロキシ）は環境変数、無ければ Windows のプロキシの設定（自動構成スクリプトは対象外）
- **GitHub・GitLab・gist の画面の URL は、中身（raw）の URL に読み替える**
- **画像も URL から取る**（設定。既定は切る）: 入れると、URL から開いた文書の相対の画像はその URL の置き場から、
  `http://`・`https://` の画像はその URL から取る（プレビュー・PDF・HTML・スライド）。切っている間は、いままでどおり
  ネットへは取りに行かない
- 起動引数 `--url <URL>` と、MCP の道具 `open_url`（新しい窓で開く。既定は「確認」）
- 作り方: Rust の HTTP の部品（ureq と rustls）を足す（OS の curl には頼らない。利用者の選択）

## 4. 対象外（v2.4.0 では入れない）

|もの|理由|
|---|---|
|MarkUpsideDown の、クラウドを使う変換・クロール（Web ページ・Office・PDF・画像 → Markdown）|ネットにつながずに全機能が使える方針と合わない（Cloudflare Workers を使う）|
|Git 連携・ファイルツリー・複数タブ|基本設計書の Won't（1 つの窓で 1 つのファイル）|
|内蔵のチャット画面|MCP（R-06）で外のクライアントから使う。MarkUpsideDown も同じ理由で廃止した|
|URL を貼るとページの題名を取る|ネットにつなぐ。v2.1.0 R-17（選んだ文字に URL を貼るとリンク）はある|
|文字の自動変換（`...` → `…` など）|今回は採らない（利用者の選択）|
|表をスプレッドシートのように直す|WYSIWYG（R-08）の表の書き換えで扱う|
|透明感を macOS・Linux で|R-05|
|本物の Mica・Acrylic（窓を透かす）|iced 0.14 が Windows で不透明の描画先しか作らない（R-05）。iced が DirectComposition に対応したら見直す|
|MCP をネットの外から使う|127.0.0.1 だけで受ける（R-06）|

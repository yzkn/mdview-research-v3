## 1. 要件

### R-01. 依存の著作権表示の一覧

（v2.5.0 の要件定義書 §5.2。v2.4.0 で見送った）

- 実行ファイルに入っている依存（いま 538 個）の、**名前・版・ライセンス・著作権表示とライセンスの全文**の一覧を作る
- 一覧は**台本**（`tools/`）で `Cargo.lock` と各依存の配布物から作り、リポジトリに置く。**依存が変わったのに一覧が古ければ CI で落とす**（公開用の複製と同じ考え方）
- 一覧は**実行ファイルに埋める**。About に「使っているソフトウェア」を足し、一覧（名前・版・ライセンス）と全文を見られるようにする
- 同梱フォントのライセンス（いまの About の表示）もこの一覧に入れる
- ライセンスの全文が配布物に無い依存は、SPDX の標準文に `Cargo.toml` の著者を入れて補い、補ったことを一覧に書く。**標準文でも補えなければ**台本が知らせて止まる（黙って抜かさない）

### R-02. URL を開くの自動構成スクリプト（PAC）

（v2.5.0 の要件定義書 §5.2。v2.4.0 R-09 は環境変数と Windows の手動のプロキシの設定だけを読む）

- **Windows**: 中継先を OS に聞く（PAC・自動検出（WPAD）・手動の設定のどれでも、OS と同じ中継先を使う）
- macOS・Linux: いまどおり環境変数（`HTTPS_PROXY` など）だけ
- 環境変数が設定されていれば、それを先に使う（いまと同じ）
- OS に聞けなかったときは直接つなぐ（いまと同じ）。どの中継先を使ったかは、つなげなかったときの知らせに出す

### R-03. frontmatter の欄

（v2.5.0 の要件定義書 §5.2。MarkUpsideDown の frontmatter パネル）

- 文書の頭の frontmatter（`---` で挟んだ YAML）を、**プレビューと WYSIWYG の頭の欄**で見せる。**畳める**（畳んだかどうかは窓ごとに覚える）
- 名前と値を並べて出す。**文字・数・真偽・日付の値と、値の並び（リスト）は欄で直せる**。名前と値を足す・消す
- 入れ子の値（対応づけの中の対応づけなど）は、欄では原文のまま出し、**原文の小窓**で直す（v2.5.1 の図・数式と同じ形）
- 裏では原文の YAML を書き換え、**触っていない行の書き方（引用符・注釈・並び順）は変えない**
- 読めない YAML は欄を出さず、その旨を小さく出す（本文の描き方はいまと同じ）
- Marp の文書の `marp: true` なども同じ欄で直せる
- 元に戻す・やり直しは、ほかの表示モードと同じ履歴
- 設定で欄を出さないこともできる

### R-04. 比べる機能を広げる

（v2.3.0 の要件定義書 §5.2。いまの 2 面の比較（v2.3.0 R-02）を土台にする）

|段|中身|
|---|---|
|R-04 a|**フォルダーの比較**。2 つのフォルダーを選び、下の階層まで見て、ファイルごとに「同じ・違う・左だけ・右だけ」を一覧に出す。違うものだけに絞れる。行を開くと、そのファイルどうしの 2 面の比較が開く（閉じると一覧に戻る）。中身は大きさと中身の照合で比べる。大きいフォルダーでも画面を止めない（比べ終わるまで進み具合を出す）|
|R-04 b|**プレビューでの比較**。いまの比較の画面の切り替え（左右に並べる・1 列に混ぜる）に「プレビュー」を足す。左右それぞれを描いて並べ、足した・消した・変わったブロック（段落・表・図など）に色の帯を付ける。左右のスクロールは揃える。読むだけ（直すときは左右に並べる出し方へ）|
|R-04 c|**3 つのファイルのマージ**。共通の元・左・右の 3 つを選ぶ。画面は**左・結果・右の 3 面**。結果は共通の元から作り、**片側だけの変更は自動で取り込む**。両側で食い違う所（衝突）には印を付け、**左を取る・右を取る・両方を取る（左が先・右が先）**で決める。結果は直接書き換えられる。次の衝突・前の衝突へ飛べる。衝突が残ったまま保存しようとしたら確かめる。結果の保存先は、保存するときに選ぶ（既定は共通の元の置き場）|

- どれも、ファイルは「アプリ内で開く」と OS のダイアログのどちらでも選べる（いまの比較と同じ）
- メニュー（ファイル → 比べる）とコマンドパレットから開く

### R-05. v2.5.1 の残りを直す

- 集中モードの最中に図・数式の小窓で Esc を押すと、小窓を閉じるだけにする（いまは集中モードも抜ける）
- 表の道具のアイコン（9 個。仮の絵）を、ほかのアイコンと見た目をそろえて描き直す
- 受入確認チェックリストの P-1〜P-3 の目視で見つかった不具合（あれば）

## 2. 設定ファイルに足す項目と設定画面

`settings.toml` に足す。**読めない値は既定値**にする（いまと同じ）。名前と細かい値は設計で決める。
**どの項目も設定画面から変えられ、項目ごとに「既定」に戻せる**（v2.1.0 R-03 と同じ）。

|機能|項目|既定|設定画面の分類|
|---|---|---|---|
|frontmatter の欄（R-03）|欄を出すか|出す|プレビュー|
|PAC（R-02）|OS に中継先を聞くか（Windows だけ）|聞く|ファイル（URL を開くの欄の隣）|
|フォルダーの比較（R-04 a）|比べないファイル・フォルダーの名前（例 `.git`・`target`）|`.git`・`node_modules`・`target`|比べる|
|マージ（R-04 c）|衝突の印の出し方（3 面だけ・結果に衝突の記号も書く）|3 面だけ|比べる|

## 3. 打鍵の割り当て（既定の案）

キー割り当ての変更（v2.1.0 R-10）の対象にする。いまの割り当てとぶつからないかは設計で確かめる。

|操作|打鍵|
|---|---|
|フォルダーを比べる・3 つのファイルをマージする（R-04）|（無し。メニューとコマンドパレット）|
|次の衝突・前の衝突へ（R-04 c）|いまの次の差分・前の差分と同じ（F7・Shift+F7）|
|左を取る・右を取る（R-04 c）|いまの片側へ写すと同じ打鍵を、マージの画面では「取る」に使う|
|frontmatter の欄を畳む・開く（R-03）|（無し。欄の頭を押す）|

## 6. 受け入れの確かめ方

v2.5.1 と同じく、単体試験と GUI 試験（`tools/automation/spec_test.py`）の項目を足し、受入確認チェックリストに目視の節を足す。
欄から書き換えた frontmatter は、**直す前と後の原文を比べる試験**で、触っていない行が変わらないことを確かめる。
マージは、衝突の無い組み合わせで結果が自動でそろうこと・衝突の印と選び方を、単体試験で確かめる。

締めに **release で組み、煙試験と `spec_test.py --perf`** を流す。
